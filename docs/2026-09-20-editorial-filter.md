## 三、四个具体毛病

### 1. 把模型发布当成了「训练论文」

写中文落地版的提示词里，把新闻分成三类：

- A 类：Agent 工程（编排、工具、记忆、MCP 这些）——保留
- B 类：模型和算法（后训练、微调、对齐这些）——删掉
- C 类：基础设施——看情况

本意是想删掉「怎么训练模型」这种和业务开发无关的论文。但 A 类的描述里**从头到尾没提「新模型发布」**。于是 AI 看到「GPT-6 发布」，归进了 B 类「模型相关」，直接删掉。

更麻烦的是，这个删除动作发生在打分之后。也就是说，前面辛苦评出来的 9.3 分，最后一步可以被推翻，而且还会写进「已筛除说明」，看起来像是编辑深思熟虑的决定。

### 2. 只限制「最多几条」，不保证「至少有几条」

当天 7 条里有 3 条是评测类论文。这不是巧合。

原来的规则只设了上限（Harness 类最多 7 条），没设下限。论文类新闻标题里常带 agent、benchmark、eval 这些词，很容易拿到 7.5 到 8.7 分；arXiv 和 HuggingFace 每天又稳定供稿。

结果就是：**只要当天论文分数高，日报就会被论文占满**。其他类型的新闻即使存在，也挤不进有限的版面。

而且「评测」和「方法论」被混为一谈了。Harbor 把 80 多个评测接口统一起来，这是能直接拿去用的工具；Tau-Tau-Bench 主要是「又出了一个新考场」，告诉你差距有多大，但读者抄不走一套做法。两者当时分数接近、待遇相同。

### 3. GitHub 项目整天一个都没有，规则还觉得正常

那天两个版本都没有一条 GitHub 项目。

规则写的是「开源项目最多推荐 2 个」，实际执行成了「0 个也合规」。几件事叠在一起：

- 没有「有合格项目就至少出 1 个」的要求
- 项目也要先过 7 分，加上跨天去重，昨天上过榜的今天就消失了
- 「开源」这个分类当时不要求真的来自 GitHub，论文附带的代码仓库也能占位

读者最后看到的「开源」，其实是论文里顺带提的「代码已开源」，不是真正值得点开的 GitHub 项目。

### 4. 官方文章有，但没提炼出东西

那天有一篇 OpenAI 官方文章，讲他们内部怎么用编码 Agent 做研究。这是最符合「一线认知」的素材。

英文版还提到了实验速度、任务复杂度这些具体内容。中文落地版压缩成了两句：

- 人话版：「内部狗粮报告，告诉你哪些工作流能加速研发」
- 开发能用上：「把可观测性做重点，记录任务拆解和失败重试」

第一句没有新信息，第二句是放之四海皆准的建议，不一定是原文重点。

缺的是一个硬性要求：**他们说了什么 → 凭什么这么说 → 所以你该改什么**。没有这个约束，官方文章会被写成和公关稿一样的「AI 能提升效率」。

### 补充：该严的反而松了

那篇 Random Attention（随机丢弃 KV 缓存）两个版本都留下了，还被写进趋势总结。它既不是模型能力，也不是 Agent 搭法，更像推理系统论文。

判断「训练类论文」的规则只认 pretrain、RLHF、DPO 这些词，KV 缓存、注意力机制这类标题对不上，就能以 7.8 分留下来。

**该留的模型发布被删，该删的系统论文留下**——两件事的根源一样：「模型/算法」这个标签太粗了。

## 四、改了什么

### 关注点重新排序

日报面向业务 Agent 开发者，关心四件事，按重要性排：

1. **Harness 方法论**——能抄走的搭法：编排、上下文管理、工具调用、记忆、MCP、评测工具、可观测性、安全、失败恢复。只发一个新评测、没有方法可抄的，不算高价值。
2. **模型能力**——已发布的模型和 API 能干什么：编码、工具调用、电脑操作、延迟和成本、上下文长度、多模态。怎么训练出来的仍然不看。
3. **官方一线认知**——OpenAI、Anthropic、DeepMind 这些团队的第一手工程文章。
4. **GitHub 开源项目**——最多 3 个，必须高度相关、能复用、有实现深度。

### 从「只设上限」改成「够格就保底」


| 分类          | 最多几条        | 至少几条  |
| ----------- | ----------- | ----- |
| Harness 方法论 | 7           | **2** |
| 模型能力        | 6           | **1** |
| 官方认知        | 4           | **1** |
| 开源项目        | **3**（原来 2） | 不强制   |


关键是：**保底只从已经够 7 分的新闻里挑**。当天没有合格内容，就让它空着，绝不凑数。

实现上，`_select_items` 先按保底数量占坑，再按分数把剩下的名额填满。

另外，「开源」这个分类现在只认真正来自 GitHub 的条目。论文带代码仓库，不能占开源的位置。

### 让三道关卡口径一致

同一条新闻要过三道 AI 判断：采集时的初筛、打分、写稿。之前三道的标准不完全一样，所以最后一道能推翻前面。

现在同一套四类标准写进了所有环节：

- 采集初筛 `src/tools/ai_filter.py`
- 重要性打分 `src/agents/extractor.py`
- 评分规则 `profiles/tech-news/analysis.md`、`match.md`
- 写稿 `src/agents/writer.py`

其中最重要的几条：

- 新模型和 API **不允许**仅仅因为「这是模型发布」就被落地版删掉
- 该删的那类收窄为真正的训练配方：预训练、后训练、微调、对齐、奖励建模
- 官方文章必须写出【核心认知】：一句主张加一句证据或启示
- GitHub 项目最多 3 个，且要说清楚哪个部分能直接拿去用

### 配置调整

GitHub 项目上限从 2 提到 3（`src/config.py` 和 `.env.example`）。采集环节的配额跟着这个值走，所以候选池也会多留一个。
